# Запись, остановка и проверка

Начни с собственной короткой тестовой встречи. Организатор запускает её,
допускает ассистента и произносит известную фразу, например: «Проект Сосна.
Антон отправит макет в пятницу». Используй вымышленные данные.

После настройки профиля `demo`:

```text
zoom.py configure run demo
```

Web-слушатель не отправляет сообщения, не включает микрофон и камеру. ИИ-анализ
отключён. Остановить CLI можно Ctrl+C один раз: дождись сохранения последнего
звука и обработки очереди. На медленном компьютере это занимает время.
Закрытие терминала или принудительное убийство процесса может оставить
неполную запись. Не называй такой запуск успешным.

Для первого запуска веди одну запись. Производительность параллельных встреч
нужно проверить на компьютере пользователя: в локальном опыте с двумя ядрами
две записи не успели обработать весь остаток STT до дедлайна стенда.

Каталог сессии выводится в конце. Проверь `status.json`, `stt-health.json`,
наличие тестовой фразы в `transcript.md`. `recording_complete: true` означает
технически завершённую запись, но не отсутствие ошибок распознавания.

Для сравнения запусков фиксируй авторизацию: событие `browser_auth` показывает,
был ли передан сохранённый вход из выбранного home. Гость и авторизованный
профиль являются разными условиями. Наличие файла не подтверждает действительность
сессии. Не выводи cookie и не переноси чужой вход без выбора аккаунта человеком.
Отказ одному гостевому запуску не доказывает отказ авторизованному пути.

Если Web сообщает `meeting_passcode_required_use_local_configure`, номер
конференции получен, но нужен код доступа. Настрой его через локальный профиль
по references/accounts.md. Не проси прислать код в чат и не меняй требования
безопасности аккаунта ради входа. Повторяй подключение после локального ввода.
`meeting_passcode_rejected` означает, что Zoom отклонил код. Не повторяй
вход с тем же значением. Человек должен сверить в Zoom строку «Код доступа»:
это отдельное значение, а не номер конференции.

`zoom_automation_blocked` означает явный запрет автоматических ботов со стороны
Zoom. Останови попытки. Не предлагай вход под видом человека, смену имени или
браузера для преодоления отказа. Запись не началась. Для разрешённой интеграции
нужен отдельный поддерживаемый Zoom путь; RTMS в этом продукте не реализован.

## Протокол

До включения модели объясни, что текст будет передан провайдеру. Затем, если
это соответствует выбору пользователя:

```text
zoom.py configure run demo --llm claude --model sonnet
zoom.py configure run demo --llm codex --model gpt-6-luna
zoom.py configure run demo --llm deepseek --model deepseek-flash
```

Текстовая граница отключает инструменты модели. Claude/Codex используют вход
пользователя в CLI; DeepSeek использует свой API-ключ. Codex CLI может включить
глобальные инструкции установленного окружения в запрос. Проверенная версия
CLI описана в `core/VERIFICATION.md`, другую не объявляй эквивалентно проверенной.

Если запись завершена, а модель дала ошибку, сохраняется расшифровка. Повторить
только протокол, указав точный каталог этой встречи:

```text
zoom.py summarize <каталог-сессии> --backend codex --model gpt-6-luna
```

Весь текст обрабатывается по частям. Проверенные части кешируются, превышение
лимита не скрывается обрезанием. Текущий результат подтверждается
`minutes-status.json` со статусом complete и SHA256 `summary.md`.
Не отдавай старый summary после ошибки повторной генерации: он может быть stale.
Самостоятельно проверь, кто что принял, к какому сроку, к какому проекту относится
реплика, какие предложения отклонены и что отменено позже.

## SDK, чат и ограничения

SDK запускается `zoom.py configure run demo --mode sdk --llm claude` после его
подготовки и с учётом экспериментального статуса SDK. При включённой LLM
он пишет ответы в чат на обращения из чата и распознанной речи;
заранее объясни это человеку. Для тихой записи используй Web.
Автоматической отправки протокола в Telegram сейчас нет. Не придумывай её.

Встреча только с чатом и без распознанной речи не получает автоматически
полноценный протокол. По голосам люди автоматически не различаются. Интерфейс
Web автоматизируется преимущественно по английским подписям; неизвестный экран
может остановить вход. Отказ доступа, ожидание допуска и работающая запись
являются разными состояниями.

## Управление через MCP

Сначала `list_meeting_profiles`, затем по просьбе пользователя
`start_web(profile_id="demo", confirm_recording=true)`. Запомни возвращённый
`session_id`; не повторяй старт при потере ответа без проверки `list_sessions`.
`session_status` показывает и worker, и запись. `stop_session` только запрашивает
остановку: опрашивай статус до завершения, затем проверь recording_complete.

Разрыв соединения AI-клиента не останавливает запись: она продолжается до
остановки или срока из профиля. Управляемые записи находятся в
`home/runs/<session_id>/sessions/`. MCP видит именно эти записи, обычные CLI
сессии остаются в `home/sessions/`. Для чтения текста вызывай read_result
страницами, пока next_offset не станет null. Не своди неполный текст как полный.

После аварийного завершения проверь приватные временные копии профиля/cookie
в каталоге runs. При штатном завершении worker удаляет свои копии; исходный
профиль и вход сохраняются. Удаление записей всегда отдельное решение человека.
