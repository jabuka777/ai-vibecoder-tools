# Аккаунты и секреты

## Личный аккаунт и отдельный аккаунт ассистента

Можно настроить оба независимых входа одновременно:

```text
zoom.py login --account personal
zoom.py login --account assistant
zoom.py login --list
```

Выполняй нужный вход или оба по просьбе пользователя. Каждый открывается в новом
браузерном контексте без cookie другого профиля. Человек выбирает нужную учётную
запись в Zoom, вводит пароль/MFA/CAPTCHA в браузере, проверяет аккаунт и нажимает
Enter в терминале. Если отдельного аккаунта ещё нет, предложи человеку создать
его обычным способом Zoom; не регистрируй сам и не читай почту для подтверждения.

Файлы хранятся раздельно: `home/accounts/personal/storage_state.json` и
`home/accounts/assistant/storage_state.json`. `login --list` показывает только
ID профиля и наличие файла, без email/cookie. Это не проверка действительности
входа. На POSIX каталоги 0700, файлы 0600; Windows ACL отдельно не проверены.

Обновить один вход: `zoom.py login --account personal --replace`.
Прежний файл сохраняется приватной резервной копией; другой аккаунт не меняется.
Перенос ранее подготовленного входа возможен только явной локальной командой
`zoom.py login --account assistant --import-state <локальный-файл>`.
Исходный файл сохраняется. Команда не проверяет владельца Zoom-сессии;
не выбирай cookie другой задачи автоматически и не читай их в контекст модели.

Привяжи аккаунт к встрече:

```text
zoom.py configure meeting demo --account personal --minutes 60
zoom.py configure run demo
```

Для отдельного аккаунта укажи `assistant` вместо `personal`. Если флаг создания
не задан, локальный мастер сначала предлагает выбрать личный аккаунт, ассистента
или гостя. Сохранённый выбор действует и при запуске через MCP. Гость задаётся
явно через `--account guest`; он не использует сохранённые входы.
Для одного CLI-запуска можно указать `configure run demo --account assistant`:
сохранённый профиль встречи не меняется. Если выбранный вход отсутствует,
запуск остановится до подключения; другой аккаунт или гость не подставляются.

Старые профили без `account` используют режим совместимости `default` и прежний
`home/storage_state.json`. Без этого старого файла сохраняется прежний гостевой
режим, явно отмеченный в журнале. Для новых встреч выбирай аккаунт явно.
Профили `personal`/`assistant` относятся к Web. SDK использует отдельную
авторизацию приложения, а не браузерные cookie; для его профиля — `--account default`.

## Общий порядок и ограничения

Для Web-слушателя приложение в Marketplace не требуется. Гостевой вход зависит
от встречи. Если Zoom просит авторизацию, запусти `zoom.py login --account <выбранный-профиль>` и предложи
человеку войти в открывшемся окне обычным доступным способом. Пароли, MFA и
CAPTCHA вводит человек. Наличие Google/Apple/SSO само по себе не означает,
что нужно создавать новый аккаунт. Корпоративные правила могут запрещать вход.

Лучше отдельный аккаунт с понятным именем записывающего ассистента. Не обещай,
что аккаунт или новый пароль снимет ограничения организатора. Не придумывай
возраст, личные данные и не принимай условия сервисов за пользователя.

После успешного входа человек нажимает Enter в терминале. Файл сохраняется
в выбранном профиле, как описано выше. Это секрет доступа: не читать в чат,
не прикладывать к отчётам и не коммитить. Файл не доказывает вход в нужную встречу.
Если вход истёк, обнови выбранный профиль через `login --account <профиль> --replace`;
не выводи cookies для диагностики.

## Профиль встречи

Создай локальный профиль, например:

```text
zoom.py configure meeting demo --account personal --name "AI-ассистент Ивана" --minutes 60
```

Ссылка или номер вводится скрыто в локальном терминале. Если в ссылке есть
`pwd`, он берётся из неё; иначе появится отдельный скрытый запрос пароля.
Файл `home/meetings/demo.json` имеет закрытые права. Обычная команда не
перезаписывает существующий профиль; для осознанной замены есть `--replace`.
На POSIX каталог meetings должен иметь 0700, файлы 0600. На Windows нужны
соответствующие права личной учётной записи; ACL вручную здесь не проверялись.

ID профиля содержит только латинские буквы, цифры, дефис и подчёркивание.
Продолжительность от 1 до 480 минут, имя до 100 символов. Профиль не подключает
к Zoom и не включает LLM. MCP принимает только ID профиля, без ссылки и пароля.

## Когда нужен SDK

Zoom не предназначает Web Meeting SDK для ботов и AI-протоколистов и указывает
RTMS: https://github.com/zoom/meetingsdk-web. RTMS здесь не реализован.
Не предлагай SDK как поддерживаемый Zoom способ запуска AI-бота. Это
экспериментальный режим для отдельно разрешённых технических проверок;
первый запуск пользователя проходит через Web с учётом правил встречи.

Для ответов в чат прочитай `core/REGISTRATION.md`. Человек создаёт разрешённое
ему приложение Meeting SDK в Zoom Marketplace и вводит credentials локально:

```text
zoom.py configure sdk
zoom.py setup-sdk
zoom.py doctor --mode sdk --backend claude --check-browser --check-model --text
```

ID и Secret сохраняются в `.env`, не в истории команд. Конфигурация других
полей сохраняется. SDK-приложение не гарантирует доступ к чужой встрече;
не обещай обход авторизации или политик Zoom.

## DeepSeek

Пользователь получает ключ в своём аккаунте провайдера и запускает
`zoom.py configure deepseek`. Ключ сохраняется только локально. Секреты нельзя
передавать аргументами MCP или сообщением ассистенту. `--llm deepseek` отдельно
разрешает передачу текста в API; установка ключа сама этого не делает.
Модель выбирается `--model`, иначе `DEEPSEEK_MODEL` или `deepseek-flash`.
Условия доступа и оплаты проверяет сам пользователь в своём аккаунте.
