# Проверки Zoom Meeting Agent

## Подготовка продукта 27 октября 2026 года

Добавлены установка отдельного окружения с возобновлением, диагностика браузера
и модели, локальный ввод секретов, скилл для Claude Code/Codex/Cursor, stdio MCP
и текстовый backend DeepSeek. Исправлены остановка дерева дочерних процессов
и распаковка SDK. При финальной сверке также исправлены остановка агента из-за
запоздавшего аудиофрагмента, обрезание цитаты внутри записи и метка времени
короткого аудиохвоста. Старые результаты ниже сохранены с границами их применимости.

На Linux прошли **233 автоматических теста без пропусков**, 35,234 с, в новом
окружении Python 3.12.3, созданном установщиком продукта. В их составе
проверены настоящий Chromium с синтетическим звуком, официальный MCP SDK 2.0.0
через stdio, блокировка одновременных запусков разными процессами, запрет
выхода за приватный каталог, ограничение числа записей, очистка дочерних
процессов и откат установки SDK на синтетическом архиве. HTTP DeepSeek
подменён; успешный ответ настоящего API и действительность ключа не проверялись.

Отдельный агент установил скилл в новый временный каталог. Все 12 команд
проверки завершились с кодом 0: исходная и установленная обёртки работают из
посторонней папки, справка передаётся нужной команде, TOML/JSON для MCP
разбираются, пути совпадают, план установки не создаёт окружение. Это проверка
инструкций агентом, а не пользовательское исследование с независимым новичком.

Установщик прошёл отдельный прогон в новом Python-окружении Linux 3.12.3.
Базовые пакеты установлены из локального wheelhouse. Отсутствующий пакет MCP
дал явную ошибку; после скачивания колёс с PyPI повтор продолжил именно этот
шаг. Ещё один повтор не переустанавливал завершённые компоненты. Проверка
браузера и модели из нового окружения завершилась с кодом 0. Chromium и модель
взяты из ранее подготовленного кеша пользователя; скачивание их с нуля новым
установщиком этим прогоном не подтверждено.

В этом же новом окружении выполнена 35-секундная запись локальной комнаты:
настоящие Chromium и Whisper, непустая расшифровка, `recording_complete: true`,
код завершения 0. Весь запуск занял 41,6 с. Запросы браузера перехвачены локально;
настоящий Zoom не вызывался. Все участники и речь синтетические.

### Отдельный стенд предыдущей версии

До этой доработки на версии `b3dd193` выполнены два чистых Linux-прогона по
122 теста и 35-секундная запись в локальной комнате с Chromium и Whisper.
Они подтверждают локальную цепочку на том снимке, а не вход в настоящий Zoom
или работу нового установщика на всех ОС.

На синтетических текстах 10 встреч по 5 генераций модель прошла 49 из 50
строгих сверок. В одном ответе пропущено непринятое предложение. Это 50
генераций, а не 50 сценариев исходной книги и не измерение «98% точности».
На двух минутах синтезированной Piper-речи Whisper small дал 17,8% WER;
предложенный порог 15% не достигнут. Речь людей и разные голоса этим не
проверены. Эти результаты не позволяют обещать протокол без ручной вычитки.

### Что остаётся проверить

- Настоящую Zoom-встречу: вход, допуск организатором, звук и завершение.
- Установку и запись на Windows/macOS; MCP сейчас требует POSIX и проверен на Linux.
- Часовую нагрузку, четыре часа непрерывной работы и поведение на слабом компьютере.
- Человеческую речь с несколькими голосами, качество имён, сроков и отмен.
- Настоящий DeepSeek API, актуальную авторизацию Claude/Codex и лимиты аккаунтов.
- Независимый первый запуск человеком без технической подготовки.

Локальные тесты не заменяют исходные 50 стендовых сценариев. Их первоначальный
статус «Не выполнен» не переписывается на «Пройден» по результату unit-теста.
Числовые пороги остаются предложениями до согласования критериев приёмки.

## Как повторить

Команды выполняются из `zoom-meeting-agent/` в установленном окружении.

Локальные тесты и проверка эталонов:

```bash
python -m unittest discover -s tests -v
python tools/evaluate_minutes.py --offline
```

`--offline` без результатов проверяет только целостность эталонов. Для повторной проверки сохранённого живого прогона без обращения к модели:

```bash
python tools/evaluate_minutes.py --offline --results tests/fixtures/eval-luna-2026-10-26/results.jsonl
```

Проверить, что исходники и материалы совпадают с зафиксированной версией:

```bash
python - <<'PY'
import hashlib
import json
from pathlib import Path

folder = Path("tests/fixtures/eval-luna-2026-10-26")
manifest = json.loads((folder / "manifest.json").read_text(encoding="utf-8"))
for root, section in ((Path("."), "source_sha256"), (folder, "artifact_sha256")):
    for name, expected in manifest[section].items():
        actual = hashlib.sha256((root / name).read_bytes()).hexdigest()
        assert actual == expected, name
print("Source and artifact hashes match")
PY
```

Новый живой прогон требует авторизованного Codex CLI **0.164.0**, отправляет синтетические тексты модели и расходует её лимит. Каталог результата должен быть новым:

```bash
python tools/evaluate_minutes.py --backend codex --model gpt-6-luna --output-dir sessions/evaluations/luna-manual-1
```

Новый ответ модели может отличаться. Его результат нужно оценивать отдельно, не переносить на него сохранённые 16/16.

## Размер модельного контекста

В ходе доработки стандартная роль coding-агента была заменена короткой ролью текстового аналитика. Ниже — метрики одного и того же первого сценария в трёх последовательных запусках:

| Запуск | Входные токены | Из них кешированные | Выходные токены |
|---|---:|---:|---:|
| Первый, до оптимизации роли | 9 659 | 6 912 | 202 |
| Второй, после оптимизации роли | 7 177 | 3 456 | 176 |
| Финальный, после уточнения промпта | 7 381 | 3 456 | 175 |

Между первым и вторым запуском вход сократился на **25,7%**; в финальном он на **23,6%** меньше первого. Одновременно менялся промпт извлечения, поэтому это наблюдение по журналам, а не изолированный эксперимент. Более низкое число входных токенов само по себе не доказывает денежную экономию: доля кеширования изменилась, а некешированный вход первого сценария вырос с 2 747 до 3 721 токена между первыми двумя запусками. Исходные числовые данные сохранены в [сравнении метрик](tests/fixtures/eval-luna-2026-10-26/token-comparison.json).

**В этих числах есть служебный контекст CLI.** Дополнительная проверка запроса через локальный имитатор провайдера обнаружила глобальные инструкции `AGENTS.md` и каталог навыков. Флаги `--ignore-user-config`, `project_doc_max_bytes=0` и отдельный файл роли не обеспечили их отсутствия. Текст встречи вместе с этим контекстом отправляется провайдеру; на другой установке состав и размер могут отличаться. Глобальные и управляемые инструкции CLI не менялись. Проверено отключение инструментов исполнения и доступа к данным, а не изоляция запроса от всех локальных инструкций.

## Границы проверки

- Проверки выполнены на Linux. Windows и macOS вручную не проверены.
- Новая версия не проходила сквозной прогон в реальном Zoom: вход, захват звука, качество STT и отправку ответа нужно проверить отдельно на своей тестовой встрече.
- Живая модель Claude в этом прогоне не использовалась. Её параметры запуска проверяются локальными тестами с подменой процесса.
- Набор инструментов настоящего Codex CLI проверяется отдельным тестом через локальный имитатор Responses API. Такой тест не вызывает модель, не доказывает качество протокола и не обещает отсутствия глобальных инструкций в запросе.
- Синтетические тексты обходят распознавание речи: эти 16 сценариев не измеряют ошибки Whisper, шум, несколько голосов, длительные встречи, поведение на других языках и затраты человека на вычитку.
- Открытые исходники, проверенные цитаты и прошедшие тесты не означают, что протокол можно исполнять без проверки человеком.
