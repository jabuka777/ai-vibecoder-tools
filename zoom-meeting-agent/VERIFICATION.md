# Проверки Zoom Meeting Agent

## Живой Web-вход отклонён Zoom

28.10.2026 попытка с приглашением настоящей тестовой встречи получила сообщение
Zoom «Automated bots aren't allowed to join this meeting».
[Обезличенный результат](tests/fixtures/acceptance-2026-10-28/live-web-rejection.json):
вход не подтверждён, звук встречи не проверен, `recording_complete: false`,
расшифровки нет. Приватная диагностика ожидала появления формы и сохраняла
метаданные экрана; это дополнение к публичному коду явно отмечено в результате.
Это один стенд и одна встреча, а не утверждение о правилах всех аккаунтов.

Использованный снимок `0cb4e1f` ошибочно обозначил этот экран как обычный запрос
авторизации. Исправленный классификатор возвращает `zoom_automation_blocked`;
проверка исправления локальная, повторного входа после явного отказа не было.
Инструкции требуют остановить попытки при таком запрете.

Последний локальный прогон после исправления: Python 3.12, 253 теста,
251 выполнен без ошибок, два optional MCP SDK пропущены, 54,468 с.
Это не подтверждение успешного Zoom-входа, CI или всех 50 сценариев приёмки.

Официальная интеграция [RTMS](https://developers.zoom.us/docs/rtms/) здесь
не реализована. Согласно [требованиям Zoom](https://developers.zoom.us/docs/rtms/troubleshooting/),
RTMS требует платного аккаунта и активного Developer Pack; Basic не поддерживается.
Для распространения приложения за пределы собственного Zoom-аккаунта нужен
[App Review](https://developers.zoom.us/docs/rtms/meetings/submit-app-review/).
Открытый исходный код сам по себе этих требований не отменяет.

## Дополнение: форма кода доступа Web

При настоящей попытке входа показана форма кода доступа и имени гостя.
Вход не подтверждён, расшифровки нет, запись отмечена неполной. Эти попытки
не засчитаны как успешный сквозной сценарий Zoom.

Исправлены явная диагностика отсутствующего кода, заполнение кода из локального
профиля и имени в форме, пропуск скрытых кнопок. Отклонённый код не отправляется
повторно автоматически. Восемь проверок формы выполнены в настоящем Chromium
на локальном HTML, без Zoom и настоящих секретов.

Дополнительная диагностика обнаружила позднее окно выбора микрофона и камеры:
действие продолжения может быть ссылкой внутри модального окна. Исправлены
обработка этого варианта и ожидание неактивной кнопки входа. Неизвестные окна
не закрываются и не обходятся. Прямой ввод в настоящую форму Zoom отдельно
завершился отклонением кода доступа; успешного входа и расшифровки нет.

Последний локальный прогон Python 3.12: 251 тест, 249 выполнены, два пропущены
из-за отсутствующего необязательного MCP SDK; ошибок нет, 53,791 с.
В первом прогоне тест завершения дерева процессов встретил `ProcessLookupError`
при исчезновении процесса между открытием и чтением `/proc`. Проверка теперь
принимает это как завершение процесса; реализация остановки не менялась.
CI и переносимость этого дополнения ещё не подтверждены. Предыдущие результаты
ниже относятся к указанным там снимкам, включая архив выпуска preview 4.

### Остановка и восстановление на последнем снимке

На [`585a666`](https://github.com/jabuka777/jabuka-tools/commit/585a66672dca324f39d86a218717567a9646a33e)
[CI выполнил 243 теста без пропусков](https://github.com/jabuka777/jabuka-tools/actions/runs/40706381979)
на Python 3.10 и 3.12. [Установка из одного ZIP](https://github.com/jabuka777/jabuka-tools/actions/runs/40706382136)
прошла на Ubuntu 24, macOS ARM64 и Windows Server 2025. На Linux/macOS
выполнены 96 компонентных тестов без пропусков; на Windows 62 выполнены,
34 пропущены: MCP, POSIX и сигналы. Windows 11 не проверена.
[Версии, шаги, пропуски и хеши](tests/fixtures/acceptance-2026-10-28/portable-installation-stop-fix.json).

Настоящий Ctrl+C в локальной комнате ранее оставлял процесс незавершённым
дольше 90 секунд. Обработчики INT/TERM теперь выставляют флаг, который проверяет
цикл записи; исключение не прерывает синхронный вызов Playwright.
[Повтор с настоящими Chromium и Whisper](tests/fixtures/acceptance-2026-10-28/stop-signals-latest.json)
сохранил по два фрагмента и завершился через 12,581 с после INT и 10,122 с после TERM.

После SIGKILL раньше оставался один STT-процесс. На Linux принадлежащие записи
дочерние процессы запускаются с `PR_SET_PDEATHSIG`; в повторе осталось ноль
наблюдавшихся дочерних процессов ещё до уборки стенда. Явно отделённый MCP worker
сохраняет прежнее поведение: переживает отключение клиента. SIGKILL не даёт
сохранить неотправленный аудиохвост, а последнее состояние может остаться recording.
Это наблюдения на Linux, без гарантии для любых потомков и других ОС.

На том же снимке [повторены N10, F23 и N15](tests/fixtures/acceptance-2026-10-28/whisper-recovery-latest.json):
плохой WebM изолирован, восстановление не добавило дубль, 15 фрагментов очереди

[Обычная локальная запись](tests/fixtures/acceptance-2026-10-28/normal-recording-latest.json)

## Как повторить

Команды выполняются из `zoom-meeting-agent/` в установленном окружении.

Локальные тесты и проверка эталонов:

```bash
python -m unittest discover -s tests -v
python tools/evaluate_minutes.py --offline
```

`--offline` без результатов проверяет только целостность эталонов. Для повторной проверки сохранённого живого прогона без обращения к модели:

```bash
python tools/evaluate_minutes.py --offline --results tests/fixtures/eval-luna-2026-10-26/results.jsonl
```

Проверить, что исходники и материалы совпадают с зафиксированной версией:

```bash
python - <<'PY'
import hashlib
import json
from pathlib import Path

folder = Path("tests/fixtures/eval-luna-2026-10-26")
manifest = json.loads((folder / "manifest.json").read_text(encoding="utf-8"))
for root, section in ((Path("."), "source_sha256"), (folder, "artifact_sha256")):
    for name, expected in manifest[section].items():
        actual = hashlib.sha256((root / name).read_bytes()).hexdigest()
        assert actual == expected, name
print("Source and artifact hashes match")
PY
```

Новый живой прогон требует авторизованного Codex CLI **0.164.0**, отправляет синтетические тексты модели и расходует её лимит. Каталог результата должен быть новым:

```bash
python tools/evaluate_minutes.py --backend codex --model gpt-6-luna --output-dir sessions/evaluations/luna-manual-1
```

Новый ответ модели может отличаться. Его результат нужно оценивать отдельно, не переносить на него сохранённые 16/16.

## Границы проверки

- Проверки выполнены на Linux. Windows и macOS вручную не проверены.
- Новая версия не проходила сквозной прогон в реальном Zoom: вход, захват звука, качество STT и отправку ответа нужно проверить отдельно на своей тестовой встрече.
- В исходном прогоне 26.10 живая модель Claude не использовалась. Один настоящий текстовый вызов 28.10 описан выше; ошибки квоты и авторизации по-прежнему проверялись подменами.
- Набор инструментов настоящего Codex CLI проверяется отдельным тестом через локальный имитатор Responses API. Такой тест не вызывает модель, не доказывает качество протокола и не обещает отсутствия глобальных инструкций в запросе.
- Синтетические тексты обходят распознавание речи: эти 16 сценариев не измеряют ошибки Whisper, шум, несколько голосов, длительные встречи, поведение на других языках и затраты человека на вычитку.
- Открытые исходники, проверенные цитаты и прошедшие тесты не означают, что протокол можно исполнять без проверки человеком.
