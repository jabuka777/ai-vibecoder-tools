# Настройка и проверка Zoom Meeting Agent

Прочитайте README.md. Сначала выберите режим Web или SDK, затем выполните
`python doctor.py`. Web не требует SDK-приложения. Для SDK следуйте
REGISTRATION.md и храните ключи только в локальном `.env`.

Для первого запуска пользователя прочитайте ../skills/zoom-meeting-agent/SKILL.md.
Он содержит порядок установки, локального ввода секретов, диагностики и MCP.
Перед записью модель Whisper нужно явно загрузить через setup_environment.py
--download-model; во время встречи STT использует только локальный кеш.

LLM по умолчанию выключена. Перед включением `--llm claude`, `--llm codex` или `--llm deepseek`
объясните передачу текста выбранному провайдеру. Никогда не включайте для
обработки речи инструменты работы с файлами, shell, MCP, приложения и плагины.
Промпт передаётся через stdin. Пароли и токены не печатайте в чат и логи.

Доступа к почте для регистрации нет: попросите человека ввести код; не гадайте.
Имя записывающего ассистента согласуйте с человеком. В чужие встречи входите
без микрофона и камеры, не отправляйте сообщения без его просьбы.

Проверка: `python -m unittest discover -s tests -v`. Отдельно прогоните
`python tools/evaluate_minutes.py --offline`. Настоящая оценка модели требует
явной команды --backend и --model; она расходует лимит. Сквозной тест Zoom
проводите только на своей тестовой встрече с вымышленной речью.

Не называйте запись успешной без состояния завершённой записи в status.json.
Протокол подтверждается minutes-status.json; старый результат может быть stale.
Это черновик с цитатами, а не гарантированно верный список поручений. Проверяйте
проекты, исполнителей, сроки, предложения и поздние отмены вручную.

Не публикуйте `.env`, `storage_state.json`, `sessions`, записи и токены.
Не выдавайте мок-тесты за живой Zoom или проверку смысла ответа настоящей модели.
Для Codex edition используйте ../zoom-meeting-agent-codex/run.py, не дублируйте ядро.
