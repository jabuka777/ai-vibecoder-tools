# Zoom Meeting Agent

**Экспериментальный инструмент.** При гостевой живой проверке 28.10.2026 Zoom явно
запретил вход автоматического бота. Авторизованный Web-вход этого кода не повторён;
отказ гостю не доказывает отказ всем режимам. Записи этой встречи нет.
Локальные тесты ниже не подтверждают работоспособность этого входа.
Разрешённый Zoom путь RTMS здесь пока не реализован.

Записывает звук Zoom-встречи и распознаёт речь локально. По явному выбору использует Claude, Codex или DeepSeek для ответов в чате и черновика протокола с цитатами.

| Режим | Скрипт | Возможности |
|---|---|---|
| SDK, экспериментальный | `bot.py` | Технический режим с ответами в чат; ограничения Zoom описаны ниже |
| Web | `webjoin.py` | Вход через веб-клиент, локальная расшифровка, протокол. В чат не пишет |

Zoom [не предназначает Web Meeting SDK для ботов и AI-протоколистов](https://github.com/zoom/meetingsdk-web)
и указывает RTMS для таких задач. Поэтому SDK-режим здесь экспериментальный,
не является поддерживаемым Zoom способом запуска AI-бота и не рекомендуется
для первого запуска. RTMS в этом продукте не реализован. Web-автоматизация
также зависит от правил и разрешений встречи; она не гарантирует обход
[защиты Zoom от ботов](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0088381).

Для отдельного запуска с Codex есть [Codex edition](../zoom-meeting-agent-codex/). Обе версии используют одно ядро: исправления записи и безопасности общие.

## Для первого запуска

Если вы только установили Claude Code, Codex или Cursor, начните с
[пошагового входа](../START_HERE.md). Скилл поможет подготовить компьютер,
войти в аккаунт, сохранить встречу и проверить запись. Отдельный сервер не нужен.

```bash
# Из корня всего репозитория; без ручной активации .venv
python skills/zoom-meeting-agent/scripts/zoom.py setup --install --download-model
python skills/zoom-meeting-agent/scripts/zoom.py doctor --check-browser --check-model --text
python skills/zoom-meeting-agent/scripts/zoom.py login --account personal
python skills/zoom-meeting-agent/scripts/zoom.py configure meeting demo --account personal
python skills/zoom-meeting-agent/scripts/zoom.py configure run demo
```

Ввод ссылки и пароля скрыт в локальном терминале. Повторная установка продолжает
незавершённые шаги и проверяет фактическое окружение. Для восстановления повреждённого
кеша модели есть отдельный `setup --download-model --repair-model`.

[Подключение MCP к клиентам](../skills/zoom-meeting-agent/references/clients.md).
Сервер даёт семь инструментов для диагностики, профилей, начала/остановки записи
и чтения результата. Две активные записи одновременно; зависший запуск занимает
слот до проверки. Записи продолжаются при отключении клиента. MCP использует
POSIX-защиту файлов; Windows MCP пока не поддерживается. Скилл и CLI доступны
отдельно. Установка проверена в CI на Ubuntu, macOS ARM64 и Windows Server 2025;
Windows 11 и реальные Zoom-встречи на этих ОС ещё не проверены.

## Установка вручную

Нужны Python 3.10+, ffmpeg, Chromium через Playwright. Node.js нужен для скачивания SDK и установки Codex CLI. Для режима Web установка Zoom SDK не требуется.

```bash
git clone https://github.com/jabuka777/jabuka-tools
cd jabuka-tools/zoom-meeting-agent
python -m venv .venv
```

Активировать окружение: `source .venv/bin/activate` на Linux/macOS, `.venv\Scripts\Activate.ps1` в Windows PowerShell.

```bash
python -m pip install -r requirements.txt
python -m playwright install chromium
python setup_environment.py --install --download-model
python doctor.py --check-browser --check-model
```

Установить ffmpeg: `brew install ffmpeg` на macOS, `winget install Gyan.FFmpeg` в Windows, `sudo apt install ffmpeg` на Ubuntu. На Linux браузеру могут понадобиться системные библиотеки: `python -m playwright install-deps chromium`.

Для ИИ-функций установите и авторизуйте [Claude Code](https://code.claude.com/docs/en/overview) или [Codex CLI](https://learn.chatgpt.com/docs/cli). Подписка или API оплачиваются отдельно. Подключение Codex проверено с CLI **0.164.0**; другая версия отклоняется до передачи текста, пока её набор инструментов не проверен.

## Запуск

### Личный аккаунт и аккаунт ассистента

Оба варианта поддерживаются через независимые браузерные профили:

```bash
python login.py --account personal
python login.py --account assistant
python login.py --list
python configure.py meeting demo --account personal
python configure.py run demo
```

Для отдельного аккаунта встречи укажите `--account assistant`. Он создаётся
самим пользователем, если его ещё нет. Пароли/MFA вводятся в браузере; входы
хранятся раздельно и не попадают в MCP или журналы. Выбранный профиль сохраняется
для встречи. `configure.py run demo --account assistant` меняет выбор только
для одного запуска. Отсутствующий выбранный вход даёт ошибку до подключения;
другой аккаунт и гость не подставляются. Гостевой режим — `--account guest`.
Обновление одного входа: `login.py --account personal --replace` с приватной
резервной копией прежнего файла. Старый одиночный вход поддерживается как
`default`; новые встречи лучше создавать с явным выбором аккаунта.
Подробности и перенос старого входа — [аккаунты](../skills/zoom-meeting-agent/references/accounts.md).

Без облачной LLM, Web:

```bash
python webjoin.py --mn 12345678901 --account personal --minutes 60
```

Если нужен пароль встречи, сохраните его в локальный файл с доступом только вам и добавьте `--password-file meeting-password.txt`. Значение пароля не передаётся аргументом процесса. Старый `--pwd` отклоняется до запуска браузера с подсказкой о новом параметре. Не добавляйте файл пароля в Git. При обычном требовании входа аккаунтом используйте `python login.py`. Явный запрет ботов (`zoom_automation_blocked`) требует остановки; авторизация под видом человека не является способом его устранить. Учётная сессия сохраняется в `storage_state.json`; не передавайте этот файл другим людям.

Протокол через выбранную модель:

```bash
python webjoin.py --mn 12345678901 --minutes 60 --llm claude --model sonnet
python webjoin.py --mn 12345678901 --minutes 60 --llm codex --model gpt-6-luna
```

SDK: настройте приложение по [REGISTRATION.md](REGISTRATION.md), заполните `.env` по примеру `.env.example`, выполните `python setup_sdk.py`.

```bash
python bot.py --mn 12345678901 --llm claude --model sonnet
```

В SDK модель отвечает на обращения, начинающиеся с «бот», имени агента или `?`, а также на голосовые «бот, …». Обычное упоминание бота внутри сообщения не вызывает ответ. Голосовой интервал между ответами составляет 30 секунд. По умолчанию допускается до 6 попыток ответа в минуту и 100 за запуск агента; лимиты задаются `--replies-per-minute` и `--max-replies`. Пропуски по лимиту и ошибки вызова видны в `agent-health.json`. Повторная ручная генерация протокола имеет отдельный лимит фрагментов. Ответы используют последние реплики, а протокол обрабатывает весь сохранённый текст.

Старые `--no-agent` для SDK и `--no-summary` для Web остаются алиасами отключения LLM. По умолчанию она уже отключена. Для ручного сообщения нужен явный каталог сессии и текстовый файл:

```bash
python say.py --session sessions/КАТАЛОГ_НУЖНОЙ_ВСТРЕЧИ --file message.txt
```

Общего `sessions/port` больше нет. Каждая встреча получает собственный порт, токен и неизменяемый `control.json`.

Чтение исходящей очереди не удаляет сообщения. Перед отправкой браузер резервирует сообщение; состояние `sent` устанавливается после успешного callback SDK. `outbox.json` хранит до 100 последних записей, включая все неподтверждённые. Ошибки сохраняются как `failed`; отсутствие callback отмечается `uncertain`. Если браузер оборвался после резервирования, останется `sending`. Такие сообщения не отправляются повторно автоматически: проверьте чат перед ручной новой отправкой. Подтверждение SDK не доказывает прочтение участником; гарантия доставки ровно один раз через сбой Zoom не заявляется.

## DeepSeek

`python configure.py deepseek` сохраняет API-ключ через скрытый локальный ввод.
После этого можно выбрать `--llm deepseek --model deepseek-flash`. Это прямой
текстовый запрос к DeepSeek API, без инструментов, браузера и MCP у модели.
Ключ не передаётся в аргументах процесса; редиректы и tool calls отвергаются,
общее время запроса ограничено отдельным процессом. Лимит/ошибка сохраняются
как ошибка протокола, запись остаётся. Автоматических платных повторов нет.
[Формат API](https://api-docs.deepseek.com/api/create-chat-completion/).
Живой DeepSeek в этом выпуске не проверялся, HTTP-ответы в тестах подменены.

## Состояние записи

`status.json` содержит `recording_complete` (не завершена / завершена / неполная) и отдельный `summary_state`. Сбой LLM не портит готовую расшифровку: протокол можно повторить. В консоли и `status.json` различаются подключение, подтверждённый вход без звука, запись, неполная запись и успешное завершение. Страница входа не считается встречей. Потеря подключения, потока звука, процесса STT или его heartbeat завершает запуск с ошибкой.

Повреждённые фрагменты сохраняются в `chunks/quarantine/`; распознавание следующих продолжается. Весь результат при этом помечается неполным. Автоматический протокол по неполной записи не формируется. Последний фрагмент выгружается перед закрытием браузера, затем STT обрабатывает остаток. `--no-stt` оставлен для говорящего тестового бота: его результат имеет состояние `untranscribed`.

Если во время записи страница перезагрузилась или сменила документ, новый экземпляр записи не может подтвердить сохранность старого. Такая сессия помечается неполной; состояние нового документа не скрывает потерю последнего фрагмента.

Новые обработанные аудиофрагменты фиксируются отдельно в `.stt-records/`. Расшифровка и `.stt_done` восстанавливаются из этих записей, поэтому остановка между их сохранением не добавляет тот же текст повторно. Историческая расшифровка до перехода на этот формат сохраняется как `.stt-base.md`; уже существовавшие старые дубли автоматически не удаляются. При свободном месте менее 64 МиБ запись останавливается с `disk_space_low` и неполным результатом.

Если уже прочитанная часть журнала изменилась или была обрезана во время работы агента, он останавливается. Родитель отмечает неполный результат; старые вопросы не воспроизводятся заново как новые обращения. Поздние аудиофрагменты при восстановлении расшифровки сортируются по времени.

## Файлы результата

Время в расшифровке обозначает оценку начала аудиофрагмента, а не точный момент
произнесения каждого слова. Она вычисляется по времени завершения записи и
числу декодированных аудиосэмплов. Задержки браузера и кодировщика остаются.
В `.stt-records/` сохранены основание метки, длительность и время конца фрагмента;
для нестандартного декодера без известной длительности используется метка конца.
Старые сохранённые метки автоматически не пересчитываются.

В `sessions/<уникальная-встреча>/`:

- `transcript.md`, `chunks/`, `events.jsonl`: исходные данные.
- `status.json`, `stt-health.json`, `stt-errors.jsonl`: состояние и причины пропусков.
- `summary.md`, `summary.json`: черновик и структурированный список фактов с источниками.
- `minutes-status.json`: завершённость обработки протокола.
- `llm-metrics.jsonl`: число символов, длительность, токены и стоимость, когда провайдер их сообщил. Текста встречи в метриках нет.

Протокол сохраняется локально целиком. Автоматическая доставка в Telegram в этой версии отключена; прежние `TELEGRAM_*` настройки не используются.

Можно повторить создание протокола по завершённой записи:

```bash
python agent.py sessions/КАТАЛОГ --summary --backend claude --model sonnet
```

Весь текст и чат разбиваются на фрагменты до 18 000 символов. Для каждой задачи, договорённости и отмены сохраняются ссылка на строку и дословная цитата. Неизвестные исполнитель, проект и срок остаются пустыми. Предложения и отмены показываются отдельно. Финальный документ не сокращается вторым вызовом модели.

Уже проверенные фрагменты повторно не отправляются, пока исходник, модель и промпт не изменились. Лимит 64 фрагмента ограничивает число вызовов. Превышение даёт явный незавершённый результат, текст не отбрасывается. Старый протокол при новой генерации помечается устаревшим и сохраняется в истории; текущий результат подтверждается `minutes-status.json`.

Проверка цитат не подтверждает правильность смысла. Особенно проверяйте исполнителя, срок, проект, отрицания и поздние отмены. Речь и чат имеют отдельный порядок; общий хронологический порядок между ними не восстанавливается. Автоматическое распределение голосов по людям не реализовано. Встреча только с чатом без аудиорасшифровки автоматически полноценный протокол не получает.

## Данные и безопасность

Поток данных: **Zoom → ваш браузер → локальные аудиофрагменты → локальный Whisper → текст**. Только с `--llm` текст встречи отправляется выбранному провайдеру: Claude, OpenAI или DeepSeek. Для CLI добавляется его служебный контекст. В проверенном Codex CLI запрос также содержит глобальные инструкции и каталог навыков установленного окружения. Zoom требует интернет; «локальное распознавание» не означает «встреча офлайн». Whisper загружается явно через setup_environment.py --download-model. Во время записи используется только локальный кеш.

Claude вызывается с пустым набором встроенных инструментов, без MCP, навыков и пользовательских hooks. Codex запускается в отдельном временном рабочем каталоге с `--ignore-user-config`; отключены инструменты команд, MCP из пользовательской конфигурации, приложений, плагинов, браузера, изображений и дочерних агентов. Режим файловой системы дополнительно установлен в read-only. Локальный тест перехватывает фактический набор инструментов запроса Codex; допускается только служебный вопрос пользователю, который в этом пакетном режиме не даёт доступа к данным. Неизвестные результаты инструментов отвергаются.

Это проверка возможностей исполнения, а не обещание отсутствия локальных инструкций в запросе. `--ignore-user-config`, `project_doc_max_bytes=0` и отдельный файл роли не исключили глобальный `AGENTS.md` и каталог навыков из проверенного запроса. Глобальные и управляемые настройки CLI не изменяются. Состав служебного контекста и расход токенов зависят от установки; подробности и результаты, в [VERIFICATION.md](VERIFICATION.md).

Документация: [Claude CLI](https://code.claude.com/docs/en/cli-reference), [Codex non-interactive](https://learn.chatgpt.com/docs/non-interactive-mode), [Codex configuration](https://learn.chatgpt.com/docs/config-file/config-reference).

HTTP слушает только loopback. Все маршруты требуют токен сессии, проверяют Host/Origin; ограничены размер запросов, очередь и число соединений. Токен добавляется браузером только к адресу этой сессии. Имена аудиофайлов проверяются, повторная запись и выход за каталог запрещены. Это не изоляция от другого процесса под той же учётной записью ОС: такой процесс может прочитать локальные файлы. Храните записи на защищённом компьютере и согласуйте участие записывающего ассистента с участниками.

Ошибки SDK сохраняются без сырых объектов с параметрами подключения, только с числовым кодом. На Linux новые каталоги сессий имеют права 0700, файлы входа и управления 0600. Windows ACL отдельно не проверялись. Записи и cookie хранятся до ручного удаления; автоматической очистки нет. Для удаления остановите процессы выбранной сессии, удалите весь её каталог вместе со скрытыми `.stt-*` и `.minutes-*`, затем при необходимости `storage_state.json` и файл пароля. Копии в резервном хранении и у провайдера LLM удаляются отдельно по правилам соответствующего сервиса.

## Проверка

```bash
python -m unittest discover -s tests -v
python tools/evaluate_minutes.py --offline
```

16 собственных синтетических сценариев не заменяют внешние 50 из первоначального разбора. `--offline` проверяет эталоны и код; качество настоящей модели этим не измеряется. Для живой проверки (передаёт вымышленные тексты провайдеру и расходует лимит):

```bash
python tools/evaluate_minutes.py --backend claude --model sonnet
python tools/evaluate_minutes.py --backend codex --model gpt-6-luna
```

Сохраняются результаты каждого сценария и метрики. Проверка сравнивает структурированные поля, цитаты и ключевые слова; произвольные равнозначные перефразы она может оценить строго.

Для сквозной проверки Zoom создайте свою тестовую встречу и запустите Web-слушателя.
Организатор или второй обычный Zoom-клиент произносит известные вымышленные фразы.
Проверьте их в `transcript.md`, `recording_complete: true` у слушателя и отсутствие
ошибок. SDK-проверки требуют отдельно разрешённого технического контура с учётом
описанных выше ограничений Zoom. Автоматические тесты не подменяют этот прогон.

## Ограничения и честная оценка

Новая версия прошла локальные тесты Linux и установку из ZIP в CI на Ubuntu,
macOS ARM64 и Windows Server 2025. Настоящий Zoom и Windows 11 требуют отдельного
прогона. [Результаты и границы](VERIFICATION.md) включают 30 минут синтетического
аудио и 50 генераций через Codex. Изменения интерфейса Zoom могут потребовать
обновления селекторов; неизвестный экран даёт ошибку, а не успешный вход.

Автоматический ввод имени и кнопки подключения Web ориентируются на английские подписи интерфейса. Некоторые русские экраны состояния распознаются, но полный вход с русским интерфейсом не проверен и не заявляется. Web записывает звук; события чата и ответы доступны в SDK-режиме.

Начальный прототип вошёл в Zoom примерно за 20 минут. Полное время установки, доработок, ошибок и ручной проверки эта цифра не описывает.
